# Release 1.7.0 / code 19

## Goal

Publish the post-1.6.0 fixes and gesture feedback redesign merged in #114 through
the build-once, exact-byte signed-candidate promotion process, retaining official
1.6.0 app data.

## Non-goals

No new app code, dependency changes, database migration, broad cleanup, upstream
sync or release-tool/protection changes in this metadata PR. Never replace an
immutable release/tag or promote a rebuilt APK after candidate approval.

## Risks

Risk level: high. Signed upgrades, player gesture/edge handling, launcher entry
trampoline (`LaunchActivity`), chat reconnection and exact-artifact approval are
release gates. Debug acceptance cannot certify the official package/signature or
upgrade. Preserve database version 36 and application ID `com.tzii.thysttv`.

## Human approval

Required before preparation/merge/signing: the maintainer's confirmation after
phone QA and review to ship 1.7.0. Required before final publication: exact
signed-candidate device acceptance, signed-RC review sign-off and successful
policy/artifact verification. No unbuilt APK is implicitly approved.

## Implementation steps

1. Merge #114 through protected `verify` (done: `3f8625e4d`).
2. Prepare this metadata-only PR (`chore/release-1.7.0`), run the full branch gate
   from `docs/RELEASE_PROCESS.md` (`test`, `lintDebug`, `assembleDebug`, unsigned
   `assembleRelease`, `site.test.js`, release workflow/metadata tests), and merge
   through strict CI without tagging.
3. Freeze `origin/master` as `$rcSha` and dispatch `release.yml` with
   `expected_rc_sha=$rcSha`. Independently verify the four-file signed bundle,
   package/version/code, official certificate, checksums and manifest binding.
4. Hand the exact signed RC APK to the maintainer for upgrade-over-1.6.0 phone QA
   and complete signed-RC review confirmation.
5. Verify both tag rulesets, create the authorized annotated `v1.7.0` tag binding
   the RC run ID and manifest digest, verify `verify_release_tag`, and promote the
   same bytes with `scripts/release/publish-release.mjs`.
6. Verify public assets, latest release and post-publication policy state; archive
   evidence outside the frozen source tree.
