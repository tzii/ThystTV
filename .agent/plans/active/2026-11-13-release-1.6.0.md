# Release 1.6.0 / code 18

## Goal

Publish the features merged since 1.5.2 through the build-once, exact-byte
signed-candidate promotion process, retaining official 1.5.2 app data.

## Non-goals

No new behavior, dependency changes, database migration, broad cleanup,
upstream sync or release-tool/protection changes in this metadata PR. Never
replace an immutable release/tag or promote a rebuilt APK after candidate approval.

## Current context

Published baseline: 1.5.2/code17 (November 2), database36. Since then master
gained Spoiler Shield (#87), integration #95 (#88–#94: protected player titles,
3-minute rewind preset, local rewind buffer, sign-in cancellation and safer
reauthorization, clip creation, chat timers) and, on November 13, #96 (download
progress card), #97 (two-pane Settings) and #98 (Watch clip / Copy link).

The maintainer tested the combined #87–#94 debug build, reported it working,
asked for the three follow-ups and asked to release today. #96–#98 passed
protected `verify` individually and were checked on the phone emulator
(downloads card states, two-pane Settings, rotation/search edge). Clip creation
needs a signed-in live session and was not run on the emulator.

## Risks

Risk level: high. Signed upgrades, a new opt-in local recording path, sign-in
token handling and exact-artifact approval are release gates. Debug acceptance
cannot certify the official package/signature or upgrade. Preserve database36
and the app ID.

## Human approval

Required before preparation/merge/signing: the maintainer's request to release
today after testing the combined debug build. Required before final
publication: exact signed-candidate device acceptance, the required reviews and
successful policy/artifact verification. No unbuilt APK is implicitly approved.

## Implementation steps

1. Merge #96–#98 through protected `verify`. Rebase this metadata-only branch on
   the resulting master.
2. Run the branch gate from `RELEASE_PROCESS.md`; merge through strict CI.
3. Freeze the post-merge master SHA and dispatch release.yml with
   expected_rc_sha. Verify the four-file signed bundle, package/version/code,
   official certificate, checksums and manifest binding.
4. Provide the exact signed APK for upgrade and device QA. Run GPT-6.1-sol/high
   and OpenCode GLM 5.3/max reviews with recorded settings and raw evidence.
   Findings that change source invalidate the candidate.
5. Verify both tag rulesets, create the authorized annotated v1.6.0 tag binding
   RC run and manifest digest, verify the tag workflow, then promote the same
   bytes with scripts/release/publish-release.mjs.
6. Verify public assets, latest release and policy state; record evidence
   outside the frozen source tree.
