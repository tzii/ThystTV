# 1.7.1 patch candidates

## Goal

A small 1.7.1 on top of 1.7.0: the bugs the 1.7.0 release reviews filed (#117, #120,
#121), the shared upstream Helix timeout bug, upstream's German translation update and,
by the maintainer's decision, the floating chat redesign (#122), each in its own
reviewable branch, then one integration debug build for emulator and phone QA. README and
site screenshots follow in their own PR once QA passes.

## Non-goals

No player lifecycle, Media3, updater, release-workflow or database change. No broad
upstream or fork import. #122 brings its own dependency (`androidx.dynamicanimation`).

## Risks

- `/timeout` now refuses arguments Helix used to receive silently; the GQL path is unchanged.
- The clip/VoD chat download now swallows chat failures (except cancellation): a download
  that used to fail outright ends as Pending instead.
- Settings restore no longer copies arbitrary bytes over the preferences file; a backup with
  a value type outside SharedPreferences' six is skipped for that key.
- Pinch: controls fade during a pinch (behavior change, gesture-QA area). The arbiter change
  only affects pinches with three or more fingers.
- German: wording changes only; no ThystTV-only string touched.
- Rewind from the beginning now asks Media3 for 1 ms. Only that start changes; "last N
  minutes" positions are never 0 unless the recording is shorter than the rewind.
- VoD controls: a state change during playback (BUFFERING, READY) only renews controls
  that are already up, so a stall or a gesture seek with the controls hidden no longer
  brings them up. Opening a VoD still shows them for 3 s (`onPlayWhenReadyChanged`,
  unchanged); paused, ended and idle are unchanged.
- Floating chat (#122): the Aa popover moves beside the card in landscape, and the chat
  container is padded under the header while it shows (the oldest line gives way).

Risk level: medium (gesture area); the other branches are low.

## Decisions

- Decision: in 1.7.1, #129 gets only the tap fix; voting stays out.
  Reason: neither ThystTV nor upstream Xtra sends poll votes or prediction bets. That needs
  new Twitch GQL mutations (and probably an integrity token, like channel points), which is a
  feature, not a patch-release fix.

- Decision: defer #118 (sign-in theme on a live dark-mode change).
  Reason: restyling the screen without recreating it means re-theming every view around the
  live WebView; recreating it loses the 2FA progress that 1.7.0 set out to keep. Minor.
  Alternatives considered: re-applying only WebView force-dark and bar icons (inconsistent).
- Decision: defer #119 (launcher trampoline theme).
  Reason: unverified on a device, and `Theme.NoDisplay` changes how Android 12+ shows the
  splash screen for a cold start; needs a light/dark device check before changing.
- Decision: restore settings through the editor rather than restarting the process.
  Reason: no lost writes or async locale storage racing an exit, values apply in memory at
  once, and a non-backup `.xml` can be rejected. The database branch still restarts.
- Decision: hide the controls when a pinch claims instead of raising the feedback overlay.
  Reason: matches seek/speed, and the floating chat PR (#122) reworks z-order in
  `fragment_player.xml`.
- Decision: no fork feature in 1.7.1 without the maintainer's pick (UI work needs the
  research-first flow). Candidates are listed in the ledger entry.
- Decision: #122 (floating chat redesign) joins 1.7.1 (maintainer, 2026-11-22). Its
  listed follow-ups (z-order over gesture feedback and the seek preview, TV D-pad focus,
  drag to untuck, haptics, custom opacity, ducking, 40dp header buttons) stay follow-ups
  unless emulator or phone QA shows one as a real problem.
- Decision: the card steps aside from the ±10 button and fades during gesture sliders
  (maintainer, 2026-11-22, after the first QA pass showed both overlaps).
  Reason: both keep the card where the viewer put it and are undone as soon as the controls
  or the slider go. Alternatives considered: moving the seek buttons, hiding the card
  during gestures, raising the gesture feedback above the card.
- Decision: the Aa popover goes beside the card where it fits, otherwise where it was.
  Reason: a placement fix, not a redesign; the panel keeps its content and the other
  menus keep theirs. Alternatives considered: a smaller panel, a bottom sheet, a
  translucent panel.
- Decision: VoD controls follow Media3 PlayerView's auto-show rule (show when the play
  button is needed or already showing). Reason: the narrowest change that stops stalls
  from opening them; `onPlayWhenReadyChanged` already covers pause and resume.
